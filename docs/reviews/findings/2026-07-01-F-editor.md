## Confirmed Findings

### FCR-M-3: `placeErase` 不检查 trap/door 占用
- **File**: [src/store/editorStore.ts:788-809](../../store/editorStore.ts#L788-L809)
- **Problem**: `placeWall` / `placeTrap` / `placeDoor` / `placePickup` 全部先调 `isOccupied`,命中发 `lastErrorKey`;**`placeErase` 没有**。如果用户擦掉一面带 trap/door 的墙,该实体孤立在 floor cell 上,既不挡路也不显形——用户感觉"消失了"。
- **Fix**: 
  ```ts
  placeErase(x, z) {
    const trapOrDoor = this._findTrapOrDoorAt(x, z);
    if (trapOrDoor) {
      this.lastErrorKey = 'editor.lastError.eraserBlockedByEntity';
      return false;
    }
    // ... existing wall removal ...
  }
  ```

### FCR-M-4: `Stepper.commit` `Math.floor` snap-down 静默改写输入
- **File**: [src/ui/editor/EditorPropertiesPanel.tsx:106-116](../../ui/editor/EditorPropertiesPanel.tsx#L106-L116)
- **Problem**: 输入 `4.6` + `step=0.5`,`Math.floor(4.6) = 4`,clamp 仍在 range 内,setDraft(4) + onChange(4)——用户看到自己输入的 4.6 被悄悄改成 4,无任何提示。
- **Fix**: 改 `Math.round`(对齐 step),或拒绝不对齐的值并显示 `editor.lastError.valueNotAligned`。

### FCR-M-5: `moveEnemyNode` NaN → 0 静默
- **File**: [src/store/editorStore.ts:1413-1414](../../store/editorStore.ts#L1413-L1414)
- **Problem**: `clamp(x, 0, size-1)`,JS 里 `NaN < 0` 是 false,`NaN > hi` 也是 false → 返回 lo = 0。`Number.isFinite` 在 `EditorPropertiesPanel` `valueAsNumber` 处有 guard,但 store 自身零防御。如果未来重构绕过 guard,NaN 注入会让路径节点瞬移到 (0, _),无任何报错。
- **Fix**: 
  ```ts
  if (!Number.isFinite(x) || !Number.isFinite(z)) {
    this.lastErrorKey = 'editor.lastError.pathOutOfBounds';
    return false;
  }
  ```

### FCR-L-3: EditorPage toast `useEffect` 陈旧闭包
- **File**: [src/ui/editor/EditorPage.tsx:143-173](../../ui/editor/EditorPage.tsx#L143-L173)
- **Problem**: `useEffect` deps 包含 `clearLastError`,Zustand `create` 每次 render 返回新引用 → effect 每次重渲染都 cleanup-then-reschedule 新 timeout,白白运行。功能正确(timeout 内调用 `clearLastError` 仍生效)但浪费。
- **Fix**: 改用 `useEditorStore.getState().clearLastError` 在 timer callback 内部调用,deps 移除 `clearLastError`:
  ```ts
  useEffect(() => {
    if (!toast) return;
    const id = setTimeout(() => {
      useEditorStore.getState().clearLastError();
    }, 3000);
    return () => clearTimeout(id);
  }, [toast]);
  ```

### FCR-L-4: `void lastError; void lastErrorKey;` TS 抑制
- **File**: [src/ui/editor/EditorTopBar.tsx:68](../../ui/editor/EditorTopBar.tsx#L68)
- **Problem**: 抑制 "unused variable" 警告,但若未来给 lastError 真实用途(如显示错误 toast),这两个 `void` 会**静默吸收**新增引用,debug 时不易察觉。
- **Fix**: 把 lastError 实际渲染到 status bar / toast 中(已有 toast 系统,集成即可),删除 `void`。
