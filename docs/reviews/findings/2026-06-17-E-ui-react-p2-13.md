### F-2026-06-17-E-M-1(回归未闭合)| `EditorPropertiesPanel.tsx:220-225, 252-264, 464-466` | `useDebouncedCommit` 闭包未修 ref 模式,每次 render 重 schedule timer

- **文件**: `src/ui/editor/EditorPropertiesPanel.tsx:220-225`
- **状态**: P2-11 评审列为 M-1,**未实际修**;P2-13 增量继续依赖 `useDebouncedCommit`(新增 tutorial 卡片也走同一 hook)。
- **影响**:
  ```tsx
  function useDebouncedCommit<T>(value: T, commit: (v: T) => void, delay: number): void {
    useEffect(() => {
      const id = window.setTimeout(() => commit(value), delay);
      return () => window.clearTimeout(id);
    }, [value, commit, delay]);
  }
  ```
  - 7 个 useDebouncedCommit 调用方,commit 都是 inline 箭头函数,引用每次 render 新建。
  - 实际效果:用户连续打 3 个字符 → 父组件 3 次 re-render → 3 个 effect cleanup + re-setup → 3 个 timer 重 schedule,只有停止打字 300ms 后才真正 commit。
  - `useEffect` 取消 + 重设 3 次 setTimeout/clearTimeout 是合理的 debounce 行为(没观察到 UX 损失),但与 React 严格模式 / Suspense / 外部 `commit` reference 变化时,会出现 "value 已变, commit 还是旧函数闭包" 的微妙 bug。
- **修复**: ref pattern(同 P2-11 推荐):
  ```tsx
  function useDebouncedCommit<T>(value: T, commit: (v: T) => void, delay: number): void {
    const valueRef = useRef(value);
    const commitRef = useRef(commit);
    valueRef.current = value;
    commitRef.current = commit;
    useEffect(() => {
      const id = window.setTimeout(() => commitRef.current(valueRef.current), delay);
      return () => window.clearTimeout(id);
    }, [delay]);
  }
  ```
- **修复优先级**: MEDIUM — 跨增量同源未修,留作技术债。

  - 弹层用 `outline: none` 是为了防止 focus ring 视觉噪音,但 `aria-activedescendant` 模式下,焦点仍在 `trigger`,弹层用 `aria-activedescendant` 指向 `option-${id}` — 这种设计下,active option 的 `:focus-visible` / `--option--active` 样式承担焦点指示。
  - `.dropdown__option--active` 视觉反差不够时,键盘用户可能不知道自己当前选中的是哪个 option(尤其在 dark mode `--fg-muted` 文字上)。
  - 看 CSS:`background: var(--accent-soft); color: var(--fg);` — active 态背景是 accent-soft 18% 透明度,在 dark mode 下是 "rgba(164, 184, 255, 0.18)" — 视觉反差有限。
- **修复**: 在 `.dropdown__option--active` 加 `outline: 2px solid var(--accent); outline-offset: -2px;` 或提高 `--accent-soft` 在 dark mode 下的可见度。
- **修复优先级**: LOW — 键盘用户场景,鼠标 hover 仍正常。
