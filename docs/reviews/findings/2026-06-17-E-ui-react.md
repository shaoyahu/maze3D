### F-2026-06-17-E-H-1 | `EditorPropertiesPanel.tsx:337` | `Segmented` 组件接收的 `options` 引用每次 render 重建,导致 indicator 位置 effect 每次 re-fire

- **文件**:`src/ui/editor/EditorPropertiesPanel.tsx:336-341`(调用点)+ `:154-205`(组件实现)
- **影响**:
  ```tsx
  // LevelMetadataForm renderBody 内
  <Segmented
    options={VICTORY_OPTIONS.map((o) => ({ value: o.value, label: t(o.labelKey) }))}
    value={victory}
    onChange={setVictory}
    testIdPrefix="meta-victory"
  />
  ```
  `Segmented` 内部:
  ```tsx
  useEffect(() => {
    const idx = options.findIndex((o) => o.value === value);
    ...
    setIndicator({ left: rect.left - containerRect.left, width: rect.width });
  }, [value, options]);
  ```
  `options` 在调用方每次 render 都是新数组(`.map` + 新 object),`useEffect` 依赖含 `options` → effect 每次 render 跑一次 → 每次 `getBoundingClientRect()` 触发 layout reflow,即使 `value` / `t` / 整个组件树没有变化。
- **重现**:
  1. 打开编辑器,任选关卡,右侧 meta panel 渲染。
  2. 移动鼠标在编辑器外 hover 触发父组件 re-render(`useShallow` 未引入,`level` 是 store selector 订阅对象)。
  3. DevTools Performance 录制 → 可见 `getBoundingClientRect` 调用频率 = render 频率。
- **修复**:两种修法,二选一:
  1. 调用方 `useMemo` 包裹:
     ```tsx
     const victoryOptions = useMemo(
       () => VICTORY_OPTIONS.map((o) => ({ value: o.value, label: t(o.labelKey) })),
       [t],
     );
     ```
     `t` 在 language 不变时 stable,`useMemo` 命中。
  2. `Segmented` 内部只依赖 `value`,把 `options` 通过 `useRef` 持有最新值(类似 `EditorViewport` 的 `cameraZoomRef` 模式),effect deps 改 `[value, containerRef.current]`。
- **修复优先级**:HIGH — 50×50 网格编辑器在 mousedown/mousemove 期间频繁 re-render(每次 store 变化 + 每次鼠标 hover readout),每帧 `getBoundingClientRect` 是不必要的 layout thrash。

## §3 MEDIUM

### F-2026-06-17-E-M-1 | `EditorPropertiesPanel.tsx:208-213` | `useDebouncedCommit` 闭包内对 `level` 的 `useEditorStore.getState().X` 间接通过 store 闭包,debounce commit 不读最新 props

- **文件**:`src/ui/editor/EditorPropertiesPanel.tsx:208-213`
- **影响**:
  ```tsx
  function useDebouncedCommit<T>(value: T, commit: (v: T) => void, delay: number): void {
    useEffect(() => {
      const id = window.setTimeout(() => commit(value), delay);
      return () => window.clearTimeout(id);
    }, [value, commit, delay]);
  }
  ```
  在 `LevelMetadataForm` 中:
  ```tsx
  useDebouncedCommit(name, (v) => updateName(v), 300);
  ...
  useEffect(() => {
    const id = window.setTimeout(() => {
      updateSize(Math.max(1, Math.floor(width)), Math.max(1, Math.floor(depth)));
    }, 300);
    return () => window.clearTimeout(id);
  }, [width, depth, updateSize]);
  ```
  `useDebouncedCommit` 的 commit callback 在 effect setup 时闭包;`useEffect` deps 包含 `commit` 参数。每次父组件 re-render,`commit` 是个内联箭头函数(新闭包),effect cleanup + re-setup → **debounce timer 总是被取消 + 重新调度**,300ms 倒计时每次 render 重新开始。结果:**用户每按一个字符,300ms 倒计时重置;只有停止打字 300ms 后才 commit**。这在大多数情况下刚好"看着对"(因为不在打字时确实 300ms 后 commit),但如果父组件持续 re-render(例如 `level` 变化触发 LevelMetadataForm re-render),`useDebouncedCommit` 内部的 `value` prop 在 commit 触发前就改变了。
- **与 React 语义矛盾**:`useDebouncedCommit` 假设 value / commit 稳定,但调用方传的内联箭头永远不稳定。React 18 严格模式下 StrictMode mount-unmount-mount 还会放大这个问题。
- **修复**:
  ```tsx
  function useDebouncedCommit<T>(value: T, commit: (v: T) => void, delay: number): void {
    const valueRef = useRef(value);
    const commitRef = useRef(commit);
    valueRef.current = value;
    commitRef.current = commit;
    useEffect(() => {
      const id = window.setTimeout(() => commitRef.current(valueRef.current), delay);
      return () => window.clearTimeout(id);
    }, [delay]);
  }
  ```
  Ref pattern:读最新 value + commit,effect 只在 delay 变化时 re-run。已在 `EditorViewport.tsx:196-197` 的 `cameraZoomRef` 见过相同模式。
- **修复优先级**:MEDIUM — 当前 300ms 内打字产生 5-6 个 timer 重置,实际未观察到的 UX 损失(因为用户最终总会停下来);但与 P2-10 之前 "useDebouncedCommit 重 schedule 5 个 timer" (B-M21) 同源,该 finding 当时未实际修。

### F-2026-06-17-E-M-2 | `EditorPropertiesPanel.tsx:430-440,488-507` | `PickupForm` / `EnemyForm` 每次 store 变化都 sync 7 个 useState,缺少 stale 闭包保护

- **文件**:`src/ui/editor/EditorPropertiesPanel.tsx:430-440,488-507,653-672`
- **影响**:
  ```tsx
  function PickupForm({ pickup }: { pickup: Pickup }): React.ReactElement {
    const [type, setType] = useState(pickup.type);
    const [value, setValue] = useState(pickup.value);
    useEffect(() => {
      setType(pickup.type);
      setValue(pickup.value);
    }, [pickup.id, pickup.type, pickup.value]);
  ```
  父组件 `EditorPropertiesPanel` 的 `useEffect` 在 `level` 变化时 re-render,`pickup` prop 重新查找。`useState` 初始化是闭包初值(只在 mount 时跑一次),**之后必须依赖 useEffect 同步**。但同步 useEffect 的 deps 是 `[pickup.id, pickup.type, pickup.value]`:
  - 用户在 input 打字 → `setValue(v)` → store update → store update 触发 `level` 变化 → 父组件 re-render → `PickupForm` re-render,`pickup.value` 是 store 最新值 → useEffect 跑 → `setValue(pickup.value)` 同值 → React 优化(同值跳过 re-render)。OK。
  - 但 `useEffect` 内部 `setValue(pickup.value)` 是无条件 set,React 18 在严格模式下会触发 bailout warning。
- **更深层问题**:`PickupForm` / `EnemyForm` 都没有被 `React.memo` 包裹,`EditorPropertiesPanel` 每次 level 变化 re-render → `renderBody` 重跑 → 命中 `<PickupForm pickup={pickup} />` → PickupForm 7 个 useState 全部 re-init check → 5 个 useDebouncedCommit 全部 re-schedule timer(B-M21 上轮发现过)。
- **修复**:
  1. `PickupForm` / `EnemyForm` / `WallForm` / `LevelMetadataForm` 全部 `React.memo`,props 用 primitive projection(`pickupId`、`type`、`value`、而非 `pickup` 对象)。
  2. `useEffect` deps 加 `pickup` 整体(并用 `pickup?.id` 区分实例)更稳。
- **修复优先级**:MEDIUM — 性能回退不严重(只在 selection 切换 / level 编辑时发生),但与 P2-10 M-21 同源。

### F-2026-06-17-E-M-3 | `EditorLeftDrawer.tsx:53-54` | `canUndo()` / `canRedo()` 在 selector 内调用,无 memo,每次 re-render 重新计算

## §8 跨切关注

1. **`useDebouncedCommit` 与 `Segmented` deps 不稳定是同一类问题**:React 闭包 + 内联函数 / 派生对象让 `useEffect` deps 失稳。推荐封装一个 `useEventCallback` 风格的 hook(在 useRef 持有 fn,deps 仅含真正可能变化的值),全 UI 统一使用。

2. **P2-11 增量引入的 4 处 i18n 漏网**:教程/HUD 卡片 6 个 label、EditorLeftDrawer 8 个 tool label、`EditorPage.DIRTY_EXIT_*` 常量 dead export。提交前 P2-8 已有"i18n 必加"惯例,但 P2-11 提交时没走 i18n checklist。下次 P2-12 增量前应补 i18n 审计。

3. **HUD 子组件 memo 状态**:5/7 已 memo(`Timer`/`Crosshair`/`InventoryBar` 内 flash 局部 memo),2/7 待补(`HealthBar`/`ControlHints`)。这两个的 props 改变频率与 tick rate 同步,补 memo 的边际收益小,但与"全 HUD memo 化"目标一致。

4. **Dialog 静态 id 仍未用 `useId`**:3 处 dialog(通用 Dialog、EditorHelpDrawer、EditorStatusBar WarningsPopup)都还在用静态字符串 `id`。`useId()` 是 React 18 的一行改动,无功能损失但 a11y 防御性提升。
